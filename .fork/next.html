Own Credentials, All the Way Down

The maintainer lives in the Windows build and logs frictions. In parallel, the agent works this board: the thesis names local models and nothing has ever answered the panel from this machine; the protocol reaches four agents and one is measured. Every item here can be built and measured without the maintainer at the desk, except where a gate says otherwise.

What this is and is not

A second horizon beside GOAL.md, not a replacement. Live in it stands until seven working days are logged; its rule that a friction which stops a turn is fixed the same day outranks every row below. This page is what the agent does on the days nothing stopped. It is a run with a definition of done, so it can be met or abandoned and then deleted.

Done when: a turn in the panel is answered by a model running on this machine, with the event log naming it and zero sockets off loopback during the turn; the picker has been measured against a list that is not Anthropic's; every agent in the survey table is filled from the wire or blocked on a credential the maintainer has declined; and the specs card says something true about every row on offer, including ?.

A model runtime, reachable from both sides

done 2026-09-07
llama-server b10844, Windows side.fork/runs/localmodel-2026-09-07/

Decided by measuring rather than by the recommendation this item carried in the morning. Under mirrored networking a loopback listener on either side answers the other, both directions checked with a throwaway server, so the side is a matter of toolchain: the official llama.cpp release ships a CUDA build for Windows and none for Linux, and no CUDA toolkit is installed in the distribution. So C:\dev\llama\b10844\llama-server.exe, unzipped and not installed, with serve.ps1 beside it, and models under X:\models\ (moved off the nearly full C: the same night). Not ollama: it has no expert-offload flag, and the strongest model that runs at agent speed on 9.6 GB of free VRAM is a 35B MoE whose experts have to live in RAM. Not LM Studio, which is installed and empty: 0.4 dropped that toggle too.

Gemma 4 12B at dynamic 4-bit is on disk and answers a Next Command-shaped request in half a second at 68 tok/s, with thinking switched off at the server, because with it on the answer is empty every time. The survey of what fits, with the two-model recommendation, is in the run README.

And the first thing it was pointed at was the four small features, which found three stale points from one upstream merge, each one layer under the last: the form refused a local URL, the settings file dropped the endpoint, the reader looked in the pre-merge vector. Fixed the same night (7529749a8, 26c376090); three of the four features then drew from the local model on the debug build, screenshots in the run.

What is still the maintainer's
  • The 22 GB Qwen3.6-35B-A3B for the panel. The machine has one disk with 49 GB free, and the fork's own builds need room on it.
Open from the run
  • The commit message in a routed WSL pane: the daemon inside the distribution generates it with its own client, where the fork's config is not installed, so on the recommended configuration this one feature is dead. The daemon should return the diff and the GUI generate; a protocol addition.

Two agents can do this without a line of fork code. opencode speaks to an OpenAI-compatible endpoint from its own config. claude-agent-acp honours ANTHROPIC_BASE_URL, and llama-server's /v1/messages answered the Anthropic shape correctly on 2026-09-07, so the recommended agent keeps every permission measurement this fork has made and swaps only the model. What is measured is the claim the fork makes in its first sentence: one turn, the event log's session_model line naming the local model, the harness transcript agreeing, and a socket census during the turn showing loopback and nothing else. The specs table gets a row with output = 0, so the cost bar is empty for the one honest reason.

Falsifier

  • The turn answers and the tool calls do not: a small model that cannot drive opencode's tools is a fact about the model, recorded, not a defect in the panel.

The specs card for a list the table cannot hand-cover

open
T21.2, the deferred halfWARP_FORK_MODEL_PRICES=fetch

Four rows were written by hand from the vendor's page. Item 1 puts hundreds on offer, and a table cannot follow them. OpenRouter's public model list carries a price per row and needs no key, so the fetch the ticket parked earns its place here: opt-in, off by default, one request per launch at most, cached under the state directory with a thirty-day age printed on the card, and refused by name unless the variable is set. It is the fork's first outbound request to a party that is not the person's own agent, which is why it is a variable and not a default, and why the egress deny-list is not the layer that decides it.

Falsifier
  • The fetch runs with the variable unset, on any path. One test pins that the request builder is never constructed without it.
  • An OpenRouter slug that does not map to the agent's id. The mapping table is still the design; the fetch only fills its numbers.

authenticate, disclosed now and sent later

open
T21.3drun: .fork/runs/acp-survey-2026-09-07/

Codex and Gemini both answer initialize with authMethods and refuse session/new without one; the fork never sends authenticate. Half of this needs no credential: when session/new is refused and the agent listed methods, the panel says so in the agent's words and names the variable. The other half, sending the method WARP_FORK_ACP_AUTH names, is a small addition measured only when a credential exists, and the credential is the maintainer's to supply or decline. Choosing the method is not Warp's, for the reason WARP_FORK_ACP_MODE has no default.
